Worked example / nightly workspace sync

Three failed jobs. A shared clue.

Instead of opening every file, the trained fly gathers three execution records within a four-read budget. The records show a sequence worth investigating:

Evidence → hypothesis

All three messages refer to the same fictional workspace-sync credential. A shared credential or refresh failure is a useful starting hypothesis.

The fly collects the records. This interpretation is supplied by the walkthrough; the fly does not prove the root cause or repair credentials.

What to check next

  1. Confirm that the jobs share the credential and inspect its expiry and refresh result.
  2. Compare the earliest authentication failure with the dependent jobs’ timestamps.
  3. After an authorized repair, rerun the sync, then the index and report; inspect the new records.

The report remains partial: eight of twelve files are unread. The synthetic test found all relevant files, but that does not establish completeness in an unknown workspace.

What the demo actually measures.

The learned scout found 100% of relevant files across these six test cases; filename matching found 0%, and seeded random reads found 44.4%. The reference filenames deliberately repeat query words, making this a simple lesson in directory and naming patterns. These are synthetic file-discovery results, not a benchmark of general diagnosis ability.

Training happens locally in your browser. The example trained fly was exported from the demonstrated browser run; the results file is an independently reproducible run using the automatic teacher. Their policy weights can differ while producing the same aggregate scores.
